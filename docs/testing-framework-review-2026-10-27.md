# DriveMate public testing framework review — 27 October 2026

Scope: source inspection of `README.md`, `.github/workflows/test-app.yml`, `.github/workflows/build-signed-apk.yml`, `.github/workflows/cat3-published-lanes.yml`, `ci/collect_results.py`, `ci/run_summary.py`, `ci/test_collect_results.py`, and the public J27-01 acceptance plan. This is a **framework review**, not proof a particular installed APK displays real UK lane advice.

## What the framework does correctly

- All inspected JVM law/decision, Android-emulator screen, and app-unit checks run **in the public `drivemate-tests` repository**, against an exact checked-out app SHA. Private app source is built on the runner; the artifact contains summaries and a picture page, not the APK. Public tests can use a same-named isolated app branch.
- `ci/collect_results.py` fails closed when a *recognised* Kotlin test method was expected but its JUnit result is absent; skips do not pass. `test-app.yml` requires every counted test to pass and zero diagnostics. The signing workflow requires a successful test workflow for the chosen app SHA and uses a separately reviewed release environment.
- Source audits and authentic UK data parser/emulator evidence are separated from legal road-marking or physical-driver acceptance. Historical source-backed full-app [#89](https://github.com/phuk-prog/drivemate-tests/actions/runs/40570944139) **273/273** and Stockport loader [#90](https://github.com/phuk-prog/drivemate-tests/actions/runs/40571143104) **270/270**; each was green on app SHA `7672b237cbbff3b78c6b42aa2c00f679b368c703`, at distinct public-test revisions. Passing these suites does **not** close Category 3 J27-01.

## Open framework risks and recommended test-first corrections

| ID | Priority | Inspected mechanism / issue | Required frozen pretest, fix and retest |
|---|---|---|---|
| **FW-01** | **High, release correctness** | `build-signed-apk.yml` locates a completed test artifact **by app SHA only** (`drivemate-tests-<sha>`). It checks workflow success but does not require its `public_tests_sha` to equal the current approved public-suite revision. A stale green suite could therefore qualify the same app SHA after new public checks were added. Manual signing approval remains a separate gate. | Construct a safe workflow test proving an old-test-revision artifact is rejected, then validate `summary.json` exact app and required public suite SHA, counts/diagnostics; trigger fresh public tests when stale; retest no valid signed-release bypass. No signing/build in the test itself. |
| **FW-02** | **High, false-green risk** | `ci/collect_results.py` assigns a category only for classnames matching `com.drivemate.tests.catNN.*(Law|Decisions|Screen)Test` or `com.drivemate.app.*`. Other source/JUnit classnames return `None`, are excluded from `found` **and** `expected`; a misnamed or differently packaged public test can be left out while the remaining suite is green. Its existing four collector regressions test missing recognised methods, not unrecognised classes. | Freeze a deliberately misnamed `@Test` source and non-category JUnit case as pretest; make collection fail closed for any unrecognised test source/result within public test locations and reject duplicate class/test identities; retest recognised full suite and reporting. |
| **FW-03** | **Medium, provenance audit trigger** | `cat3-published-lanes.yml` PR trigger paths list only `ci/audit_published_manchester_lanes.py` and the workflow file. Changes only to the frozen source JSON and production-`LaneDb` test resources do **not** trigger this separate source audit. The main full-app workflow still runs on PRs. | Add the published-source fixture/resource and corresponding tests to audit workflow trigger paths; include a negative test that mismatched source content/digest fails audit; rerun public audits. Never regard OSM tags alone as legal truth. |
| **FW-04** | **Medium, category coverage and batches** | `ci/collect_results.py` maps friendly category labels only for **1–10**; later categories fall back to generic `catNN`. The inspected `README.md` explains category/kind but no explicit register-driven batch grouping of related tests (2–4 at a time) or `correct/fail/unknown/provisional` denominator enforcement. | Add complete master category names through 22, explicit batch manifest mapping public tests to register IDs, frozen UK source and acceptance state. Keep law/decision/screen distinct and independently validate legal truth. Report reasons and counts without treating unknown as a pass. |
| **FW-05** | **High, Category 3 release acceptance** | Generic `summary.json` supports `passed/failed/skipped` and diagnostics; it does **not** establish actual independently verified eligible-junction denominators or source → `NavigationSession.nav.lanes` → visible screen. Thus all-green fixtures cannot settle real-driver missing-lane incident J27-01. | Keep J27-01 **open**; add a separate frozen source-backed real-route acceptance ledger with exact app/test/map SHAs, correct/total, failed/unknown/provisional, screenshots and suppression-reason trace, online/offline/reroute. Require verified legal layout evidence; never manufacture arrows or claim physical testing. |

## Change boundaries

This audit creates **no test-code, workflow, app, map, APK, signing or production behaviour changes**. Each proposed framework correction must be tested first in the **public** repository on a separate branch/PR, with the identical frozen pretest rerun after implementation. Preserve historical green evidence and clearly distinguish observed incidents from inferred framework risks. Link these items from the private master `REGISTER.md` and retain Category 3 open until independently verified.
